About

Applications built end to end, with AI where it helps

I'm a Software Engineer based in Belgium. I build modern applications from the interface to the backend, and I integrate language models into them, connecting AI to application data, APIs and workflows.

Focus

What I concentrate on

  1. Modern, end-to-end applications

    Interface, API and data layer designed together, so a feature works from the first click to the database.

  2. AI inside practical products

    Language-model features added where they solve a real problem, with a clear view of what they cannot do.

  3. Models connected to real data

    Controlled access to application data, APIs and workflows, instead of loose prompts detached from the system.

  4. Maintainable, dependable backends

    Layered code, explicit error handling, and tests around the parts that matter most.

  5. Emerging AI, applied with care

    I keep exploring new AI technology and adopt it where it provides genuine value.

Approach

How I approach engineering problems

Each of these is something the code in my projects does, with a link to where.

  1. Keep boundaries clear

    Routes, services and repositories stay separate, so a model, a database or an API can change without rewriting the rest.

    CleverStudy architecture

  2. Treat model output as untrusted

    A model's answer is input like any other: parse it, check its shape, escape it, and decide what happens when it is wrong.

    Output validation

  3. Expect upstream failures

    Quota limits and API errors are normal conditions. They get their own exceptions, a fallback and visible states.

    Fallback and errors

  4. Give models narrow access

    Where a model needs data, I prefer small read-only tools over copying a database into a prompt.

    Tool design

  5. Test what protects the most

    Authentication and data access come first. The rest is still to do, and the case study says so.

    Test coverage and limits
