UMC School Management System

A school administration system on Laravel 12 and Filament, with an assistant that answers questions from live records by calling typed, read-only tools.

Status

Started

Type
Full-stack web application

muridabuhamed/UMC-project

Overview

The application manages the records a school needs day to day: students, teachers, departments, courses, enrollments, grades, attendance, schedules, fee payments and communication logs. Administrators work in a Filament panel with dashboards, bulk attendance entry and CSV exports. Teachers get a scoped view of their own courses and students.

On top of that data sits an AI assistant built on Google Gemini. Asked in plain language, it can look up a student's grades or attendance, or summarise a department, using the school's live records.

Engineering challenge

A language model that only sees a prompt cannot know a student's grades. The obvious fix is to paste the data into the prompt, but that sends more records to a third-party model than a question needs, grows with the database, and makes every answer slower and more expensive.

The assistant needed a way to ask for exactly the records relevant to a question, while the application stays in control of what is queried.

Architecture and implementation

  1. QuestionAn admin asks in the Filament assistant page (Livewire).
  2. Gemini chatHistory is rebuilt each turn; four function declarations are attached.
  3. Function callThe model names a tool and its arguments.
  4. Tool classA registry maps the name to an MCP tool that runs an Eloquent query.
  5. AnswerThe result goes back to Gemini, which writes the reply. The loop repeats while the model keeps calling tools.

Data and access control

A Filament admin panel on Laravel 12 sits over 11 Eloquent models and 25 migrations. Access is handled with Spatie roles (super_admin and teacher) through Filament Shield, one policy per resource, and query scoping: for teachers, the course, grade, schedule and student resources are filtered to their own records.

The assistant

The assistant is a Filament page backed by Livewire. It keeps the message list, rebuilds the Gemini chat history on every turn, declares four functions (search_student_by_name, get_student_grades, get_student_attendance, get_department_summary) and runs a loop: while the model answers with a function call, the application executes it and sends the result back.

MCP server

The query logic lives in four tool classes built with the Laravel MCP package. Each has a description and a typed input schema. A SchoolServer class exposes the same four tools to external MCP clients, over stdio (php artisan mcp:start school) and over an HTTP route.

Other AI features

An executive health report is generated with Gemini for super admins only and cached for 12 hours. Student pages can generate a summary and recommendations. A command-center modal takes the other approach: it builds a text summary of school data (counts, teachers, the top five students) and puts it in the prompt.

Key technical decisions

Tool calling for the assistant

Giving the model functions instead of data means it only receives what it asks for, and each lookup is an ordinary, inspectable query. The command-center modal shows the alternative in the same codebase: simpler to write, but it ships a fixed summary on every request, including teacher email addresses, to a third-party API.

Query logic in MCP tool classes

Keeping each query in a tool class gives one place for the logic, and the same classes can serve both the in-app assistant and outside MCP clients. A registry maps each Gemini function name to its tool class:

The trade-off is visible here: the function declarations the assistant sends to Gemini are written out in the page, and each tool class declares its own schema again. The two can drift apart.

Read-only tools

All four tools only query: student search, grades, attendance and a department summary. The model can look data up but cannot change it.

Cached reports

The executive report is restricted to super admins and cached for 12 hours, which bounds the number of API calls it can cause.

Current status and limitations

In development. The first commit is from 10 May 2026 and most features were built over the following five weeks. It is not meant for real student data yet:

  • Automated tests are limited to Laravel's default examples, so the tool loop and the scoping rules are untested.
  • Access control around the assistant's data tools and the MCP endpoint is not finished.
  • The tool loop has no iteration limit, and errors from the model call are shown to the user as text.
  • Student and teacher data is sent to the Gemini API inside prompts. A real deployment would need a data-protection review.
